VaultCore — настольное приложение для фиксации намерения. Вы пишете текст, приложение фиксирует время UTC и подписывает его ключом Ed25519. Получатель вставляет код и видит: содержимое не менялось, подпись сделана именно этим автором.

Как это работает

Три действия
и ни одного сервера

Никаких аккаунтов, регистраций и облаков. Приложение ставится на компьютер, работает с локальным ключом и передаёт документ так же, как обычный файл — почтой, мессенджером или распечаткой.

01 — ПЕЧАТАЕТЕ

Заголовок и текст

Заявление, обещание, условия сделки, черновик договора или шутка — до 100 000 символов. Текст нормализуется: переводы строк и пробелы по краям фиксируются однозначно.

02 — ЗАПЕЧАТЫВАЕТЕ

Подпись и время

Одно нажатие: фиксируется дата UTC, считается SHA-256 от версии, ключа, заголовка, текста и времени, ставится подпись Ed25519. После этого поля блокируются навсегда.

Код POI2,
разобранный до байта

Документ — это не PDF. Это шесть подписанных полей: версия, открытый ключ автора, заголовок, текст, время и подпись. Всё остальное — способы доставить эти байты получателю. По этой странице можно написать независимый верификатор.

6 полей в полезной нагрузке
32 байта открытый ключ Ed25519
64 байта подпись Ed25519
420 000 байт — предел разбора кода
01 · Контейнер

Одна строка,
ноль двусмысленностей

Код — это префикс POI2. и полезная нагрузка в base64url без выравнивания. Декодер обязан отвергать padding, не-UTF-8 и любую неканоническую запись.

code = "POI2." + base64url_nopad( utf8( json_payload ) )
02 · Полезная нагрузка

Ровно шесть полей

Все обязательны, лишние запрещены. Дубликаты ключей запрещены. Размер — не больше 420 000 байт.

ПолеТипОграничения
vцелоестрого 2 — версия формата
pkстрокаbase64url, ровно 32 байта: открытый ключ Ed25519 автора, каноническая запись
titleстрокадо 200 символов, одна строка, нормализован
textстрокаот 1 до 100 000 символов, нормализован
tsстрокаровно YYYY-MM-DDThh:mm:ssZ, UTC
sigстрокаbase64url, ровно 64 байта: подпись Ed25519

Ключ автора входит в подписанные байты — подменить pk, не сломав подпись, нельзя. Дайджест в коде не передаётся: верификатор всегда пересчитывает его сам.

03 · Канонические байты

Подписывается
не JSON-строка

Строка «как есть» — источник неоднозначности: одна и та же пара полей может дать разные байты. Здесь каждое поле упаковано с префиксом длины, поэтому границы полей невозможно перепутать.

Преобразование

DOMAIN "proofofintent.code.v2"
frame("2") версия формата
frame(pk) открытый ключ автора
frame(title) заголовок после нормализации
frame(text) текст документа
frame(ts) UTC, до секунды
frame(x) = u32_be(len(x)) ‖ x
digest = SHA-256(preimage)
sig   = Ed25519.sign(digest)
preimageбез JSON
# подписывается 32-байтовый дайджест,
# штатным Ed25519 (не Ed25519ph)
DOMAIN  = b"proofofintent.code.v2"

preimage = (
    DOMAIN
    + frame(b"2")
    + frame(pk.encode())
    + frame(title.encode("utf-8"))
    + frame(text.encode("utf-8"))
    + frame(ts.encode())
)

digest = hashlib.sha256(preimage).digest()
sig    = private_key.sign(digest)   # 64 байта
04 · Алгоритм проверки

Четыре шага,
два возможных ответа

Никакой сети, никаких запросов к серверу времени или ключа. Всё, что нужно, уже лежит в коде документа.

01 — РАЗОБРАТЬ

Строгий JSON

base64url → UTF-8 → объект. Набор ключей ровно {v,pk,title,text,ts,sig}. Лишнее поле — отказ.

02 — ПЕРЕСЧИТАТЬ

Дайджест

SHA-256 от канонических байтов. Переданному дайджесту не доверяют — его всегда считают заново.

03 — СВЕРИТЬ

Подпись

Ed25519.verify(pk из документа, digest, sig). Не сходится — содержимое не показывается.

✓
Подпись верна

Документ подлинный, содержимое не изменялось. Рядом показывается отпечаток ключа автора для сверки по независимому каналу.

≠
Другой ключ

Если ожидаемый ключ передан или вшит в сборку и не совпал — статус «подписан другим ключом», содержимое скрыто.

✕
Изменено

Правка текста, заголовка или даты ломает подпись. Документ помечается как изменённый.

05 · Тестовый вектор

Проверьте
свою реализацию

Детерминированный вектор с демонстрационным ключом (000102…1f, не настоящий). Если ваш верификатор выдаёт для него «подлинный» — математика сходится.

fingerprint_short = 56:47:5A:A7

Забрать целиком

Полный код POI2.… из вектора. Его можно сохранить как файл .poi и открыть в приложении во вкладке «Проверка».

06 · Совместимость

Правила, которые
не меняются молча

v1

Коды POI1. не поддерживаются: ключ стал частью подписываемых данных, старые коды отвергаются с сообщением о версии.

v3

Любое изменение состава полей — это v=3, префикс POI3. и новый DOMAIN. Совместимость не подразумевается.

Дизайн

Оформление PDF не входит в подпись, поэтому печать, шрифты и шаблон можно менять, не ломая уже выданные документы.

Доверие

Вера в «правильный» ключ — отдельный слой: вшитый при сборке ключ или отпечаток, присланный автором по другому каналу.

Ключи и документы установщик не трогает. Приватный ключ живёт в хранилище учётной записи Windows, а ваши .poi и PDF — там, куда вы их сохранили. Переустановка или удаление программы их не удаляют.

cmdтихая установка 
:: поставить без окон в свою папку
VaultCore-Setup.exe --silent --dir "D:\Apps\VaultCore"

:: без ярлыков и без записи в «Программы»
VaultCore-Setup.exe --silent --no-shortcuts --no-registry

:: удалить
VaultCore-Setup.exe --uninstall --silent
Ключи установщика
--silent

Без интерфейса, код возврата 0 или 1.

--dir

Свой каталог установки вместо %LOCALAPPDATA%\Programs\VaultCore.

--no-shortcuts

Не создавать ярлыки в «Пуске» и на рабочем столе.

--no-registry

Не писать запись в «Программы и компоненты».

--uninstall

Удаление; с --silent — без подтверждения.

--keep-self

Не удалять каталог установки после удаления.
